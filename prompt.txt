## 2. Project Overview & Core Features

**grocery-list-app** is a responsive, fast, intuitive grocery shopping and inventory management application designed for seamless in-store mobile use and desktop planning.

### Key Capabilities:
- **List & Item Management**:
  - Create, view, rename, and switch between multiple grocery lists (e.g., "Weekly Groceries", "Costco Run", "Dinner Party").
  - Auto-seed a default "Weekly Groceries" list when no lists exist.
  - Add items with name, quantity, unit (pcs, kg, lbs, pack, bunch, gallons, etc.), category, priority (low, medium, high), and optional notes.
  - Interactive item completion toggle (check off items as you shop) with visual strike-through and collapsible completed items section.
  - Edit item details inline or via accessible modal/drawer.
  - Delete items individually or batch-clear completed items.
  - Quick quantity stepper (`+` and `-`) for rapid in-aisle adjustments.
- **Categorization & Filtering**:
  - Default categories with distinct color-coded badges and icons (Produce, Dairy & Eggs, Bakery, Meat & Seafood, Pantry, Frozen, Beverages, Household, Snacks, Other).
  - Ability to add custom categories.
  - Category grouping view (organizes the shopping list by supermarket aisles/sections).
  - Real-time search bar with instant filtering by item name or note.
  - Status filters: `All`, `Active / Pending`, `Completed`.
  - Sorting options: By Category (Aisle order), Alphabetical (A-Z), Priority, Recently Added.
- **User Experience & Responsiveness**:
  - Mobile-first, touch-friendly UI optimized for one-handed phone use in a grocery store aisle.
  - Optimistic UI updates with toast notifications for actions, rollbacks, and network errors.
  - Dark mode and light mode support with system preference detection and manual toggle.

## 5. Backend REST API Specifications

The backend serves a JSON REST API and binds to `0.0.0.0` listening on `process.env.PORT || 8080`.

### Endpoints:
- `GET /health` or `GET /api/health`
  - Response `200 OK`:
    ```json
    { "status": "healthy", "service": "grocery-list-app-api", "timestamp": "2026-10-11T19:20:00.000Z" }
    ```
- `GET /api/lists`
  - Returns array of all lists. If none exist, automatically seeds and returns the default "Weekly Groceries" list.
- `POST /api/lists`
  - Request Body: `{ "name": string, "description"?: string }`
  - Response `201 Created` with created list object.
- `GET /api/lists/:listId`
  - Returns list details and item counts (`totalItems`, `completedItems`).
- `DELETE /api/lists/:listId`
  - Deletes the list and cascades deletion to all associated items.
- `GET /api/items`
  - Query parameters:
    - `listId` (optional string)
    - `category` (optional string)
    - `isCompleted` (optional boolean string: `'true'` or `'false'`)
    - `search` (optional string, case-insensitive substring match on name/notes)
  - Returns array of grocery items.
- `POST /api/items`
  - Request Body:
    ```json
    {
      "listId": "list_weekly_groceries",
      "name": "Bananas",
      "quantity": 1,
      "unit": "bunch",
      "category": "Produce",
      "priority": "medium",
      "notes": ""
    }
    ```
  - Response `201 Created` with created item document.
- `GET /api/items/:id`
  - Returns single item.
- `PATCH /api/items/:id`
  - Request Body: Partial item fields (e.g., `{ "isCompleted": true }`, `{ "quantity": 3 }`).
  - Response `200 OK` with updated item.
- `DELETE /api/items/:id`
  - Deletes the item. Response `204 No Content` or `200 OK`.
- `POST /api/items/clear-completed`
  - Request Body: `{ "listId": string }`
  - Batch deletes all completed items belonging to `listId`. Response: `{ "deletedCount": number }`.

### Standards & Middleware:
- CORS middleware configured to accept `http://localhost:*`, all Vercel deployment preview domains (`https://*.vercel.app`), and custom domains.
- `express.json()` body parser.
- Centralized error handler returning `{ "error": { "code": string, "message": string } }` with appropriate HTTP status codes (400, 404, 500).

## 9. Deployment Architecture & CI/CD Pipelines

Both backend and frontend deployments must be bulletproof, accounting for the common points of failure in Cloud Run source builds and Vercel monorepo builds.

### 1. Backend: Google Cloud Run Deployment
- **Target Project**: `ai-learning-499409`
- **Service Name**: `grocery-list-app-api`
- **Region**: `us-central1`
- **Mandatory Cloud Run Source-Deploy Rules**:
  - **Source Deployment Mandate**: MUST use source-based deployment:
    ```bash
    gcloud run deploy grocery-list-app-api \
      --source . \
      --project ai-learning-499409 \
      --region us-central1 \
      --platform managed \
      --allow-unauthenticated \
      --port 8080
    ```
  - **DO NOT** use `docker build`, `docker push`, or `--image`. Cloud Run source deployment packages and compiles the code directly.
  - **CRITICAL PORT RESTRICTION**: **NEVER** set `PORT` in `--set-env-vars` or `--update-env-vars` on Cloud Run. Setting `PORT` as an environment variable will cause Cloud Run deployment to fail. Cloud Run sets `PORT` automatically; the deployment flag must specify `--port 8080` to instruct Cloud Run which port the container listens on.
  - **Buildpack & Runtime Packaging (`backend/package.json`)**:
    - Cloud Run source deploy uses Google Cloud Buildpacks. The `backend/package.json` must include:
      ```json
      "scripts": {
        "build": "tsc",
        "start": "node dist/server.js",
        "prestart": "npm run build"
      }
      ```
    - Ensure all dependencies required at runtime are in `"dependencies"`, and TypeScript compiler tools are properly accessible during buildpack compilation.
    - Provide a `backend/.gcloudignore` file to prevent uploading `node_modules`, test coverage, and local environment files:
      ```text
      .git
      .gitignore
      node_modules/
      coverage/
      *.log
      .env
      ```
- **Backend GitHub Actions Workflow (`.github/workflows/deploy-backend.yml`)**:
  ```yaml
  name: Deploy Backend to Google Cloud Run

  on:
    push:
      branches: [ main ]
      paths:
        - 'backend/**'
        - '.github/workflows/deploy-backend.yml'
    workflow_dispatch:

  jobs:
    deploy:
      name: Test & Deploy Backend
      runs-on: ubuntu-latest
      defaults:
        run:
          working-directory: backend

      steps:
        - name: Checkout Code
          uses: actions/checkout@v4

        - name: Setup Node.js
          uses: actions/setup-node@v4
          with:
            node-version: 20
            cache: 'npm'
            cache-dependency-path: backend/package-lock.json

        - name: Install Dependencies
          run: npm ci

        - name: Run Tests
          run: npm test

        - name: Build TypeScript
          run: npm run build

        - name: Authenticate to Google Cloud
          uses: google-github-actions/auth@v2
          with:
            credentials_json: ${{ secrets.GCP_SA_KEY }}

        - name: Set up Cloud SDK
          uses: google-github-actions/setup-gcloud@v2

        - name: Deploy to Cloud Run (Source Deploy)
          run: |
            gcloud run deploy grocery-list-app-api \
              --source . \
              --project ai-learning-499409 \
              --region us-central1 \
              --platform managed \
              --allow-unauthenticated \
              --port 8080 \
              --set-env-vars "NODE_ENV=production,GCP_PROJECT_ID=ai-learning-499409,FIRESTORE_COLLECTION=grocery-list-app,CORS_ORIGIN=*"
  ```
