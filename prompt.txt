## 2. Project Overview & Core Features

**grocery-list-app** is a responsive, fast, intuitive grocery shopping and inventory management application designed for seamless in-store mobile use and desktop planning, with default dark theme styling and a live cloud connection to a Google Cloud Run API and Google Cloud Firestore.

### Key Capabilities:
- **Default Dark Theme & Visual Polish**:
  - **Default View is Dark Theme**: The application initializes in dark mode by default (`class="dark"` applied to the root document on initial render).
  - Modern, high-contrast dark aesthetic (slate/zinc dark backgrounds, vibrant accent badges, crisp typography) optimized for battery efficiency and low-glare grocery store aisles.
  - Manual theme toggle in the header allowing users to switch between Dark and Light mode.
  - Theme preference persisted in `localStorage` under key `grocery_theme` (defaulting to `'dark'` when no preference is saved).
- **List & Item Management**:
  - Create, view, rename, and switch between multiple grocery lists (e.g., "Weekly Groceries", "Costco Run", "Dinner Party").
  - Auto-seed a default "Weekly Groceries" list when no lists exist.
  - Add items with name, quantity, unit (pcs, kg, lbs, pack, bunch, gallons, etc.), category, priority (low, medium, high), and optional notes.
  - Interactive item completion toggle (check off items as you shop) with visual strike-through and collapsible completed items section.
  - Edit item details inline or via accessible modal/drawer.
  - Delete items individually or batch-clear completed items.
  - Quick quantity stepper (`+` and `-`) for rapid in-aisle adjustments.
- **Categorization & Filtering**:
  - Default categories with distinct color-coded badges and icons (Produce, Dairy & Eggs, Bakery, Meat & Seafood, Pantry, Frozen, Beverages, Household, Snacks, Other).
  - Ability to add custom categories.
  - Category grouping view (organizes the shopping list by supermarket aisles/sections).
  - Real-time search bar with instant filtering by item name or note.
  - Status filters: `All`, `Active / Pending`, `Completed`.
  - Sorting options: By Category (Aisle order), Alphabetical (A-Z), Priority, Recently Added.
- **Backend Connection & Reliability (Cloud Run Integration)**:
  - **Live Deployed Connection**: The UI connects directly to the live deployed Google Cloud Run backend (`grocery-list-app-api`).
  - **Multi-Tier API URL Resolution Hierarchy**:
    1. `localStorage` custom override (`grocery_api_url`): Allows instant live updates from the UI without redeployment.
    2. Build-time environment variable `import.meta.env.VITE_API_URL`.
    3. Production Default Fallback Cloud Run URL (`https://grocery-list-app-api-bdxnar4rza-uc.a.run.app`).
    4. Local development fallback: `http://localhost:8080`.
  - **Connection Status & Diagnostic Manager**:
    - Live health badge in the UI header indicating connectivity status (`Connected`, `Checking...`, `Disconnected`).
    - An interactive "API Connection Settings" modal accessible from the header and from error banners. Allows users to view current API URL, enter a custom endpoint, click "Test Connection" (`/health`), and persist the verified URL to `localStorage`.
    - Automated Doctype/HTML interception that explains the exact issue and provides a 1-click action to switch to the active Cloud Run URL.
- **User Experience & Responsiveness**:
  - Mobile-first, touch-friendly UI optimized for one-handed phone use in a grocery store aisle (minimum 44x44px touch targets).
  - Optimistic UI updates with toast notifications for actions, rollbacks, and network errors.

## 5. Backend REST API Specifications

The backend serves a JSON REST API and **MUST explicitly bind to `0.0.0.0`** listening on `process.env.PORT || 8080`.
*(Binding to `127.0.0.1` or `localhost` is strictly prohibited as it causes Cloud Run container health check failures).*

```typescript
const PORT = parseInt(process.env.PORT || '8080', 10);
const HOST = '0.0.0.0';
app.listen(PORT, HOST, () => {
  console.log(`grocery-list-app-api listening on ${HOST}:${PORT}`);
});
```

### Endpoints:
- `GET /health` or `GET /api/health`
  - Response `200 OK`:
    ```json
    { "status": "healthy", "service": "grocery-list-app-api", "timestamp": "2026-10-11T19:20:00.000Z" }
    ```
- `GET /api/lists`
  - Returns array of all lists. If none exist, automatically seeds and returns the default "Weekly Groceries" list.
- `POST /api/lists`
  - Request Body: `{ "name": string, "description"?: string }`
  - Response `201 Created` with created list object.
- `GET /api/lists/:listId`
  - Returns list details and item counts (`totalItems`, `completedItems`).
- `DELETE /api/lists/:listId`
  - Deletes the list and cascades deletion to all associated items.
- `GET /api/items`
  - Query parameters:
    - `listId` (optional string)
    - `category` (optional string)
    - `isCompleted` (optional boolean string: `'true'` or `'false'`)
    - `search` (optional string, case-insensitive substring match on name/notes)
  - Returns array of grocery items.
- `POST /api/items`
  - Request Body:
    ```json
    {
      "listId": "list_weekly_groceries",
      "name": "Bananas",
      "quantity": 1,
      "unit": "bunch",
      "category": "Produce",
      "priority": "medium",
      "notes": ""
    }
    ```
  - Response `201 Created` with created item document.
- `GET /api/items/:id`
  - Returns single item.
- `PATCH /api/items/:id`
  - Request Body: Partial item fields (e.g., `{ "isCompleted": true }`, `{ "quantity": 3 }`).
  - Response `200 OK` with updated item.
- `DELETE /api/items/:id`
  - Deletes the item. Response `204 No Content` or `200 OK`.
- `POST /api/items/clear-completed`
  - Request Body: `{ "listId": string }`
  - Batch deletes all completed items belonging to `listId`. Response: `{ "deletedCount": number }`.
- `ALL *` (Unmatched API Routes Catch-All):
  - Must return a valid JSON 404 response with `Content-Type: application/json` (`{ "error": { "code": "NOT_FOUND", "message": "Endpoint not found" } }`) so that unmatched backend routes never return HTML error pages to API clients.

### Standards & Middleware:
- CORS middleware configured to accept `*`, `http://localhost:*`, all Vercel deployment preview domains (`https://*.vercel.app`), and production custom domains.
- Express json body parser: `app.use(express.json())`.
- Centralized error handler returning `{ "error": { "code": string, "message": string } }` with appropriate HTTP status codes (400, 404, 500) and explicit `Content-Type: application/json`.

### 2. Preventing & Resolving the HTML Doctype / Unconnected Backend Issue:
In Single-Page Applications deployed on Vercel, requests to relative `/api/...` endpoints or requests when `VITE_API_URL` is empty trigger Vercel's SPA rewrite (`/(.*) -> /index.html`). Vercel returns `index.html` (which starts with `<!doctype html>`) with HTTP status 200. Calling `.json()` on this response produces:
`Unexpected token '<', "<!doctype "... is not valid JSON`.

To eliminate this entirely and ensure the UI is **always connected** to the deployed Cloud Run backend, implement the following multi-tier connection architecture.

#### Multi-Tier Backend URL Resolution (`frontend/src/api/client.ts`):
Define a predictable production fallback pointing directly to the deployed Cloud Run service, alongside `localStorage` and `VITE_API_URL`:

```typescript
// frontend/src/api/client.ts

// Verified production Cloud Run default deployed URL for project ai-learning-499409 / service grocery-list-app-api
export const DEFAULT_PRODUCTION_API_URL = 'https://grocery-list-app-api-bdxnar4rza-uc.a.run.app';

export function getApiBaseUrl(): string {
  // 1. Manual runtime override saved in browser storage
  if (typeof window !== 'undefined') {
    const saved = localStorage.getItem('grocery_api_url');
    if (saved && saved.trim() !== '') {
      return saved.trim().replace(/\/+$/, '');
    }
  }

  // 2. Build-time Vite environment variable
  const envUrl = import.meta.env.VITE_API_URL;
  if (envUrl && envUrl.trim() !== '') {
    return envUrl.trim().replace(/\/+$/, '');
  }

  // 3. Localhost development fallback
  if (typeof window !== 'undefined' && (window.location.hostname === 'localhost' || window.location.hostname === '127.0.0.1')) {
    return 'http://localhost:8080';
  }

  // 4. Default Production Cloud Run Service URL fallback
  return DEFAULT_PRODUCTION_API_URL;
}

export function setApiBaseUrl(url: string): void {
  if (typeof window !== 'undefined') {
    if (!url || url.trim() === '') {
      localStorage.removeItem('grocery_api_url');
    } else {
      localStorage.setItem('grocery_api_url', url.trim().replace(/\/+$/, ''));
    }
  }
}

export async function checkBackendHealth(targetUrl?: string): Promise<{ healthy: boolean; message: string }> {
  const base = targetUrl ? targetUrl.trim().replace(/\/+$/, '') : getApiBaseUrl();
  try {
    const response = await fetch(`${base}/health`, { credentials: 'omit' });
    const contentType = response.headers.get('content-type') || '';
    if (!contentType.includes('application/json')) {
      return { healthy: false, message: 'Endpoint returned non-JSON / HTML page.' };
    }
    const data = await response.json();
    if (data.status === 'healthy' || data.service === 'grocery-list-app-api') {
      return { healthy: true, message: 'Connected to Cloud Run API' };
    }
    return { healthy: false, message: `Unexpected response status: ${data.status}` };
  } catch (err: any) {
    return { healthy: false, message: err.message || 'Unable to connect' };
  }
}

export async function apiRequest<T>(endpoint: string, options: RequestInit = {}): Promise<T> {
  const baseUrl = getApiBaseUrl();
  const url = endpoint.startsWith('http') ? endpoint : `${baseUrl}${endpoint}`;

  let response: Response;
  try {
    response = await fetch(url, {
      ...options,
      headers: {
        'Accept': 'application/json',
        'Content-Type': 'application/json',
        ...options.headers,
      },
    });
  } catch (networkError: any) {
    throw new Error(`Failed to reach backend at ${url}. Details: ${networkError.message}`);
  }

  const contentType = response.headers.get('content-type') || '';
  if (!contentType.includes('application/json')) {
    const rawText = await response.text();
    if (rawText.trim().toLowerCase().startsWith('<!doctype') || rawText.includes('<html')) {
      throw new Error(
        `Received HTML instead of JSON from ${url}. The frontend is contacting a static server instead of the Cloud Run API. Please use the Connection Settings to configure the active Cloud Run URL.`
      );
    }
    throw new Error(`Unexpected non-JSON response from ${url}: ${rawText.slice(0, 100)}`);
  }

  const data = await response.json();
  if (!response.ok) {
    throw new Error(data?.error?.message || `API error with status ${response.status}`);
  }
  return data as T;
}
```
