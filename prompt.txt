## 2. Project Overview & Core Features

**grocery-list-app** is a responsive, fast, intuitive grocery shopping and inventory management application.

### Key Capabilities:
- **List & Item Management**:
  - Create, view, rename, and switch between multiple grocery lists (e.g., "Weekly Groceries", "Costco Run", "Dinner Party").
  - Add items with name, quantity, unit (pcs, kg, lbs, pack, etc.), category, priority, and optional notes.
  - Interactive item completion toggle (check off items as you shop) with visual strike-through and optional collapsible completed section.
  - Edit item details inline or via modal.
  - Delete items individually or batch-clear completed items.
  - Quick quantity stepper (`+` and `-`) for rapid shopping adjustments.
- **Categorization & Filtering**:
  - Default categories with distinct color-coded badges and icons (Produce, Dairy & Eggs, Bakery, Meat & Seafood, Pantry, Frozen, Beverages, Household, Snacks, Other).
  - Ability to add custom categories.
  - Category grouping view (organizes the shopping list by supermarket aisles/sections).
  - Search bar with instant real-time filtering by item name or note.
  - Status filters: All, Active / Pending, Completed.
  - Sorting options: By Category (Aisle order), Alphabetical (A-Z), Priority, Recently Added.
- **User Experience & Responsiveness**:
  - Mobile-first, touch-friendly UI optimized for one-handed phone use in a grocery store aisle.
  - Optimistic UI updates with toast notifications for actions and errors.
  - Dark mode and light mode support with seamless toggle.

## 5. Backend REST API Specifications

The backend must serve a JSON REST API and listen on the port provided by the environment (`process.env.PORT || 8080`).

### Endpoints:
- `GET /health` or `GET /api/health`
  - Response `200 OK`: `{ "status": "healthy", "service": "grocery-list-app-api", "timestamp": "..." }`
- `GET /api/lists`
  - Returns array of all lists. If none exists, auto-seed a default "Weekly Groceries" list.
- `POST /api/lists`
  - Body: `{ "name": string, "description"?: string }`
  - Returns `201 Created` with created list object.
- `GET /api/lists/:listId`
  - Returns list details and summary counts (total items, completed items).
- `DELETE /api/lists/:listId`
  - Deletes the list and cascades deletion to its items.
- `GET /api/items`
  - Query parameters:
    - `listId` (optional, filter by specific list)
    - `category` (optional, filter by category)
    - `isCompleted` (optional boolean, filter by status)
    - `search` (optional string, fuzzy/substring match on name/notes)
  - Returns array of grocery items.
- `POST /api/items`
  - Body:
    ```json
    {
      "listId": "list_weekly_groceries",
      "name": "Bananas",
      "quantity": 1,
      "unit": "bunch",
      "category": "Produce",
      "priority": "medium",
      "notes": ""
    }
    ```
  - Returns `201 Created` with created item document.
- `GET /api/items/:id`
  - Returns single item.
- `PATCH /api/items/:id`
  - Supports partial updates (e.g. toggling `isCompleted: true`, updating `quantity`, changing `category`).
  - Returns `200 OK` with updated item.
- `DELETE /api/items/:id`
  - Deletes the item. Returns `200 OK` or `204 No Content`.
- `POST /api/items/clear-completed`
  - Query / Body: `{ "listId": string }`
  - Batch deletes all completed items in the given list.

### Standards & Middleware:
- CORS middleware allowing Vercel production frontend domains and `http://localhost:*`.
- Request body parser (`express.json()`).
- Centralized error handler returning consistent format: `{ "error": { "code": "NOT_FOUND", "message": "..." } }`.

## 6. Frontend Specifications & User Interface

- **Component Hierarchy**:
  - `Header`: App branding, active list selector dropdown, new list button, dark/light theme switcher.
  - `FilterBar`: Search input with clear button, category filter dropdown/chips, status filter tabs (`All`, `Active`, `Done`).
  - `AddItemForm`: Quick-entry bar with autocomplete/category inference (e.g., typing "Apples" auto-suggests "Produce"), quantity stepper, unit selector, and "Add" button.
  - `GroceryList`: Grouped or flat list rendering `GroceryItemCard` components.
  - `GroceryItemCard`:
    - Large checkbox / tap target for quick check/uncheck.
    - Title with completed strikethrough styling.
    - Category pill with distinctive colors.
    - Quantity & unit badge.
    - Inline edit and delete buttons.
  - `EmptyState`: Contextual illustrated message when list is empty or search returns 0 results.
  - `BatchActionsBar`: Sticky bottom or top bar showing "X completed items" with a "Clear Completed" button.
- **Optimistic UI**: Checking an item immediately updates the UI; if the network fails, roll back state and display a toast alert.

## 9. Deployment & CI/CD Pipelines

### 1. Backend Deployment: Google Cloud Run
- **Target Project**: `ai-learning-499409`
- **Service Name**: `grocery-list-app-api`
- **Region**: `us-central1`
- **CRITICAL RULES for Cloud Run**:
  - **Source Deployment Mandate**: MUST use source-based deployment:
    ```bash
    gcloud run deploy grocery-list-app-api \
      --source . \
      --project ai-learning-499409 \
      --region us-central1 \
      --platform managed \
      --allow-unauthenticated \
      --port 8080
    ```
  - **DO NOT** use `docker build`, `docker push`, or `--image`. Cloud Run source deployment will automatically build and package the code.
  - **NEVER** set `PORT` in `--set-env-vars` or `--update-env-vars` on Cloud Run. Cloud Run manages the `PORT` environment variable internally. Always specify `--port 8080` as the container listening port flag.
- **GitHub Actions Workflow** (`.github/workflows/deploy-backend.yml`):
  - Triggers on push to `main` branch when changes occur in `backend/**`.
  - Authenticates using Google Cloud Workload Identity Federation or Service Account Key secret (`GCP_SA_KEY`).
  - Runs tests.
  - Deploys backend via `gcloud run deploy grocery-list-app-api --source ./backend ...`.

### 2. Frontend Deployment: Vercel
- **Vercel Scope / Team**: `noam-projects2`
- **Vercel Project Name**: `grocery-list-app-ui`
- **GitHub Actions Workflow** (`.github/workflows/deploy-frontend.yml`):
  - Triggers on push to `main` branch when changes occur in `frontend/**`.
  - Uses `VERCEL_TOKEN`, `VERCEL_ORG_ID`, and `VERCEL_PROJECT_ID`.
  - Injects `VITE_API_URL` pointing to the deployed Cloud Run backend service.
  - Runs tests, builds with Vercel CLI (`vercel pull --environment=production`, `vercel build --prod`, `vercel deploy --prebuilt --prod`).
